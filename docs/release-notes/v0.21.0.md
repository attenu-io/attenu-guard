# 0.21.0 — 2026-10-18

Bundle corpus revision `bundle_vectors_v1.5` and the trust-set document (#35). The entries below are the CHANGELOG text for this release; the design and limits of the trust-set document are in `docs/TRUST-SET-FRESHNESS.md`.

### Added
- **Bundle vectors revision `bundle_vectors_v1.5`** (twenty-nine cases): entry validation and the first `schema_version=1` chains. Nine cases appended: `valid_bundle_v1` (accept; the `valid_bundle_v2` run as a v1 chain, seven entries, no `outcome` entry and no v2-only field), `reject_unknown_ledger_fields`, `reject_v2_field_on_v1`, `reject_unknown_ledger_event`, `reject_outcome_event_on_v1` (an `outcome` entry on a v1 chain carrying only v1 field names), `reject_invalid_ledger_entry` and `reject_invalid_ledger_entry_array` (chain-level, `seq` and `node` null), `valid_bundle_v1_ungated_allow` (accept, `expect_report` `actions_checked` 2, `ungated` 1) and `reject_unknown_policy_value_v1_chain` (`invalid_policy` AND `containment` on seq 5; proposed by safal207 on A2A #1575). Every earlier row was a v2 chain and none exercised the rules that read an entry whole: with `unknown_ledger_fields`, `v2_field_on_v1`, `unknown_ledger_event`, `invalid_ledger_entry` or `invalid_policy` deleted, a verifier still scored all twenty (reported for the first two by a third-party verifier on A2A #1575; reproduced for all five on this verifier, where each deletion fails the v1.5 rows named for it). No row carries any of the nine field names no published entry carries, and a test pins that. The twenty earlier cases are byte-identical and `version` stays `bundle_vectors_v1`; the corpus description and `tests/vectors/README.md` no longer say every bundle is v2. attenu-guard-ts scores all twenty-nine to the same outcome and the same failure list
- **A trust set may be a document whose `not_after` bounds every row** (#35). `witness_keys` (and `--witness-keys FILE`) may be `{"witness_keys": [rows], "not_after": ...}`; at or after the set's `not_after`, compared with the same verification time as a row's, no row is trusted and every envelope fails the existing `envelope_unknown_witness`; for a key the set held, the message says the trust set expired. A row without `not_after` is no longer trusted forever inside such a document. The document is read whole: another member, rows that are not an array, or a `not_after` outside the row grammar raise `ValueError`. Design and limits, including why the signed statement #35 proposed is not built: `docs/TRUST-SET-FRESHNESS.md`
- `docs/THREAT-MODEL.md`: `not_after` protects against staleness for a reader whose clock is right, and not against an adversary who holds that clock. The reader compares it with its own UTC clock or a caller-passed `now`; the CLI passes none

### Changed
- `--witness-keys FILE`: a JSON object with `bundle` and `witness_keys` members is a vector case, as before; any other object with `witness_keys` is now a trust-set document, read whole, so an object with `witness_keys` and a misspelled `notAfter` is refused instead of read for its rows. An object with both `bundle` and `not_after` is refused ("a vector case carries no not_after; a trust-set document carries no bundle"), since read as a vector case its expiry would be dropped. A vector case is not read whole: a misspelled `notAfter` on a vector case is ignored and the case still verifies; "is refused" applies to the document form only. The not-a-trust-set message now ends "or an object carrying one as witness_keys". A mapping passed to the library with a `witness_keys` member is a document, so the `{kid: key}` form cannot name a kid `witness_keys`
